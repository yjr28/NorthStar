# Architecture

## Design goals

NorthStar is split across native and managed components to model real server-management boundaries:

1. Low-level host observation without direct control-plane OS access.
2. Stable agent/control-plane contracts.
3. Durable host, telemetry, and command state.
4. Hybrid deployment across local KVM infrastructure and AWS.
5. Reproducible benchmarks instead of estimated scale claims.

## Data path

```text
/proc + sysinfo -> C collector -> C++ agent -> HTTP/JSON -> Java control plane -> PostgreSQL
                                                  ^
                                                  |
                                         fleet simulator
```

The collector owns Linux metric acquisition. The agent owns identity and transport. The control plane owns API contracts, liveness, persistence, and command state.

## Current invariants

- Host IDs are UUIDs and may be generated by the agent.
- Re-registering a host refreshes metadata and liveness.
- Telemetry is append-only and refreshes liveness.
- Commands are queued, polled, and explicitly acknowledged.
- Deleting a host cascades to telemetry and command state.
- Telemetry query limits are bounded server-side.

## Next upgrades

Agent credentials and rotation; idempotency keys; cursor pagination; command lease semantics; OpenTelemetry + Prometheus; retry/backoff and offline buffering; PostgreSQL partitioning; Terraform/Ansible deployment for AWS and KVM.
